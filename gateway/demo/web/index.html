THE IDEA BEHIND THE MOTION

A changing route. A familiar destination.

The address changes at the transport layer. Your page, form, and business API stay the same.

01

Time creates the token

The client and gateway use the same seed and time window to calculate an eight-character HMAC token.

HMAC(seed, floor(time / window))
02

The gateway checks it

Current and previous-window tokens pass. Missing, altered, future, and expired tokens get a 404 before the proxy runs.

current ✓   previous ✓   expired ✕
03

The backend stays simple

The gateway strips the token. Your service receives its original endpoint and processes the request normally.

/api/v1/{token}/checkout → /api/v1/checkout
What does this protect against—and what does it not do?

This demonstrates moving-target route obfuscation. It is not authentication or DDoS protection. Browser-held seeds can be extracted, and valid tokens can be replayed during their acceptance window. Production services still need TLS, authentication, authorization, rate limiting, and backend isolation. This local dashboard intentionally exposes test tokens, including future and expired ones; it does not disclose the seed. “Forwarded” means the proxy was invoked; “backend response” means an upstream HTTP response was received. Gateway time is measured on the server, not a network benchmark.
